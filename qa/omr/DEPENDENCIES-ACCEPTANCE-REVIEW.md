# بوابة قبول التكامل بعد الحزمة الثانية

## الحكم: غير مقبول للنشر بعد

استخدم الاختبار الحزمتين الأصليتين المفكوكتين، دون طلبهما مجددًا أو الاتصال بالإنتاج. تجاوز إدخال الطالب العائق السابق ونُفّذت المراجعة والاعتماد والتراجع عن ورقة غير منشورة، لكن نشر محاولة الطالب والتراجع عنها بدرجتها لم يكتمل.

الاختبار: `qa/omr/sql/dependencies-integration.py`.
الدليل المنقّح: `qa/omr/results/dependencies-integration/evidence.json`.

## نتائج هذه الجولة

**16 تحققًا ناجحًا** في PostgreSQL 17.6 محلي، دون فشل assertions. يتضمن ذلك إثبات الذرية عند فشل النشر؛ لا يعني نجاح النشر نفسه.

| المسار | النتيجة المثبتة |
|---|---|
| إدخال الطالب وربطه بهوية اصطناعية | نجح بالمحفزات الأصلية؛ استُدعيت `nafes_normalize_arabic` الأصلية فعليًا |
| المراجعة اليدوية | نجحت بدور `service_role`؛ السبب في `after_answer.manual_reason` ورقم الإصدار زاد |
| الإجابة الملتبسة | رفض اعتمادها قبل الحسم؛ ثم نجح اعتماد الورقة والدفعة بعد الحسم |
| كتابة المحاولات والدرجات | محجوب داخل المزامنة الأصلية؛ لم تُنشأ أي محاولة |
| ذرية فشل كتابة المحاولات | صفر محاولات وصفر اختبارات جزئية بعد الفشل؛ بقي سجل المراجعة اليدوية |
| صلاحية التراجع | رُفض المعلم محدود المادة دون حذف أو إنشاء سجل تراجع |
| تراجع المعلم العام عن ورقة غير منشورة | نجح؛ حُفظ سجل التدقيق وحُذفت الورقة المستهدفة |
| إعادة طلب التراجع نفسه | اكتُشف replay؛ لم يتكرر سجل التدقيق |
| التراجع عن محاولة منشورة وتأثيره على التجميع | غير مثبت؛ لا محاولة مكتملة منشورة في هذه البيئة |
| API/PostgREST الفعلي | غير مختبر؛ لا تُنسب اختبارات RPC المحلية إليه |

لم تُعد تجربة الصور الـ140 أو مجموعة الانحدار الـ155؛ لم تتغير شيفرة القارئ أو الحفظ التنفيذية. أدلتها السابقة تبقى محفوظة ولا تُحتسب اختبارات نشر محاولات ناجحة.

## العائق الخارجي الوحيد: المصدر الأصلي ليس مغلق التبعيات ومكتمل البيانات التعريفية

أُغلقت الأسماء الخمسة السابقة بالفعل. لكن التنفيذ الأصلي كشف نواقص تالية:

### تعريفات وظائف غير موجودة في الحزمتين

- `auth.uid`
- `private.moallimi_touch_updated_at`
- `public.lugati_sync_exam_attempt`
- `public.lugati_norm_training_text`
- `public.nafes_content_fingerprint`
- `public.nafes_question_quality_checks`
- `public.nafes_question_quality_hard_pass`
- `public.nafes_reviewed_content_key`

قد تقود هذه الوظائف إلى تبعيات أخرى؛ لم تُركب نسخ تاريخية أو دوال بديلة.

### أخطاء تركيب مثبتة في تمثيل المصدر المرفق، لا إثباتًا لخلل الإنتاج

1. **`auth.users`:** نُقلت `confirmed_at` كقيمة `default` تحتوي مرجع أعمدة، دون وصف `generated`. PostgreSQL رفضها: `cannot use column reference in DEFAULT expression`. لا يمكن تحويلها إلى عمود مولّد بالتخمين.
2. **`moallimi_classes`:** القيمة الافتراضية والسياسة تستدعيان `auth.uid()` غير المرفقة؛ وللجدول محفز أصلي في مخطط `private`.
3. **بنك الأسئلة:** تركيب CHECK الأصلي رفض لغياب `nafes_reviewed_content_key(text,text,jsonb,text)`. أُلغي تركيب الجدول كله بمعاملة؛ لم يُبقَ جدول جزئي بلا قيوده.
4. **سجل الاستبعاد:** الإدراج من محفز الطالب رفض لأن `id` لا يحمل قيمة افتراضية أو metadata هوية في الحزمة: `null value in column "id" ... violates not-null constraint`. لم يُضف تسلسل أو identity مفترض.
5. **المزامنة:** محاولة النشر وصلت إلى استدعاء المزامنة ثم توقفت عند `public.nafes_exam_attempts`. تعريف الجدول موجود؛ تركيبه الأصلي محجوب بوالداته `auth.users` و`moallimi_classes`. ليست المشكلة غياب الجدول في الإنتاج.

### حدود إثبات الصلاحيات

استُخدمت ACL المرفقة لخمسة جداول مسح وسجل الحذف والوظائف التسع والخمس. قائمة `omr_table_acl` تحتوي `nafes_scan_deletions` بدلًا من `nafes_paper_reviews`؛ ACL الأخير الأصلي غير مرفق.

ACL الأصلي لوظائف scan RPC وصلاحيات المخططات والتسلسلات ليست في الحزمة. يحتفظ الاختبار بحماية RPC التطويرية السابقة، ويُعلّم صراحة أن صلاحية قراءة `paper_reviews` تطويرية. لذلك لا يصح وصف هذه البيئة بأنها نسخة مطابقة لكل تفويض Supabase الأصلي.

## طريقة سد نقص المصدر دون إعادة طلب الحزمتين أو مفتاحهما

الاستعلام الموجود `qa/omr/export/manual-review-metadata-readonly.sql` يصدّر attributes الهوية والتوليد، ويتبع تبعيات القيم الافتراضية والقيود والمحَفزات، ويشمل مخطط `private` عند الوصول إليه، مع ACL. ناتجه الكامل هو المصدر المطلوب لإغلاق هذه الفجوات، لا إعادة رفع الملفات المستلمة نفسها.

## ما حُفظ وما لم يتغير

- أضيف اختبار تكامل جديد ودليل نتائج خاص بهذه الجولة فقط.
- لم تُغير شيفرة الإصلاح التنفيذية لأن الفشل المثبت متعلق بتركيب المصدر الناقص، لا عطل يمكن إصلاحه بأمان داخل التطبيق.
- التعريفات المفكوكة بقيت خارج المستودع. الدليل لا يحتوي تعريفات خاصة أو بيانات حقيقية.
- لم تُنشأ قاعدة إنتاجية أو تُعدل درجات، ولم يحدث نشر إلى Supabase أو GitHub Pages.
- بوابة النشر تبقى مغلقة حتى نجاح دورة المحاولات والدرجات والتراجع عنها والصلاحيات عبر النقل الفعلي.
