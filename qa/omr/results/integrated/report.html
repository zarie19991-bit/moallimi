# معلّمي — تقرير الدمج النهائي المحلي

## الحكم: غير جاهز للنشر

حُفظت نسخة تطوير من المصدر المنشور المرفوع للدالة `nafes-exam`، ولم تُستبدل بنسخة GitHub الأقدم.
لم يحدث اتصال بقاعدة Supabase الإنتاجية، أو تغيير درجات حقيقية، أو نشر.

## ما أُنجز فعليًا

- لوحة مراجعة إضافية داخل نسخة من صفحة `student-papers.html` الحالية، مع الحفاظ على الواجهة والأصول الأصلية.
- فصل أسباب القراءة والهوية ومفتاح التصحيح، وعدم عرض المرشحين كاختيار مؤكد.
- سبب إلزامي للتعديل اليدوي وتعيين الهوية؛ إظهار سجل تعديلات الإجابة والهوية.
- إعادة القراءة بعد المراجعة البشرية تُنتج اقتراحًا فقط؛ لا تمحو الاختيار أو إصدار الإجابة أو سجل التعديلات.
- حراس SQL للحفظ والتكرار والاعتماد والإصدارات والتزامن، دون تعطيل المحفزات الأصلية.
- تقييد جميع تواقيع RPC الحفظ والمراجعة والنشر والتراجع بدور الخادم، لا الاكتفاء باستقبال UUID المراجع من متصل عام.
- تعديل مصدر نشر التصحيحات لربط الطالب بـ UUID فقط، دون مطابقة اسم قد تختار طالبًا آخر.
- استبدال كتابة المحاولات المتتابعة باستدعاء RPC معاملاتي واحد، يحفظ النتائج وبيانات المراجعة معًا.
- الإبقاء على المحاولة الموجودة والمُسلّمة دون تحديثها؛ إعادة الطلب المطابق تعيد النتيجة الموجودة، والتعارض يحتاج تراجعًا مصرحًا.
- إصلاح مُرحّل في مصدر التراجع: صلاحية المراجع وملكيته، كشف إعادة الطلب والتعارض، حفظ سجل التعديلات قبل الحذف، رفض المحاولات المختلطة أو غير التابعة، وتقييد التنفيذ بدور الخادم.
- فتح جلسة مغلقة أو فك مرجع تكرار بعد التراجع يتطلب سجل حذف تابعًا للمعاملة الحالية؛ متغير الجلسة وحده لا يكفي.

**تمييز ضروري:** إصلاح النشر والتراجع موجود في المصدر وSQL المرحّل، لكنه غير معتمد للنشر؛ لم يُختبر مساره الإيجابي كاملًا بسبب التعريفات الناقصة أدناه. أزراره محجوبة محليًا؛ هذا ليس نجاحًا بديلًا عن الاختبار.

أُدخلت حالة غموض اصطناعية واحدة **بعد القراءة** لاختبار سير المراجعة، وليست خطأ قراءة في الصورة.
رُفض اعتمادها بلا حسم، ثم حُسمت وفق الحقيقة المولدة بسبب مسجل؛ سجل التعديل بقي محفوظًا.
المراجعة النهائية تحتوي 8400 اختيار مطابق، و140 ورقة معتمدة في قاعدة الاختبار.
هذا لا يعني إنشاء 140 محاولة طالب منشورة: **لم تُنشأ محاولات** لأن تعريفات المصدر اللازمة غير مكتملة.

اختبار المتصفح كشف خطأ عرض سبب التعديل: السبب محفوظ في `after_answer.manual_reason` لا في حقل أعلى السجل؛ أُصلح العرض وأُعيد الاختبار بنجاح.
كشف أيضًا تعارض ترقيم السؤال مع SQL، وتم توحيده على 1–60.

الاختبارات لا تثبت صحة الأوراق القديمة ذات الدرجات الحقيقية أو دقة كل صورة مادية محتملة.
الإجابات المقارنة هنا هي الحقيقة المولدة لصور اصطناعية، لا سجلات طلاب ولا تخمينات.

## العوائق الحقيقية، وما ينقص تحديدًا

التعريفات الأساسية الست وجدول `nafes_teacher_access` متوفرة ومستخدمة؛ لا يلزم إعادة استخراجها.
المطلوب لإغلاق التكامل الإيجابي للنشر والتراجع:

1. تعريف `nafes_scan_deletions` الأصلي: الأعمدة وأنواعها وافتراضياتها والقيود والفهارس والمحفزات وRLS وسياسات الوصول والصلاحيات.
2. تعريفا والدي المحاولات الأصليان `nafes_assessments` و`nafes_students`، بنفس عناصر المخطط السابقة.
3. التعريف والتوقيع الأصليان لـ `lugati_sync_sections_attempt` و`lugati_sync_student_worksheets` وتبعياتهما الفعلية. يستدعيهما محفزا المحاولات الأصليان.
4. إغلاق صلاحيات/سياسات الجداول التابعة، للتحقق من مسار Edge/PostgREST بدور الخدمة الحقيقي. الاختبار المحلي الحالي يستخدم مالك PostgreSQL، ولا يثبت صلاحيات خدمة Supabase.

تعريف `nafes_assessment_attempts` ومُحفز عدم تعديل المحاولة المُسلّمة متوفران.
لا يمكن تركيب الجدول بكل علاقاته ومُحفزاته دون والديه والمساعدين.
لم تُنشأ بدائل لهذه المكونات، ولم تُحذف العلاقات أو تُعطّل المحفزات للحصول على نجاح شكلي.

**الاختبارات المحجوبة:**
- تراجع مصرح ناجح من دفعة منشورة، مع حفظ تاريخها وإعادة معالجة بقايا الدفعة.
- إنشاء/ربط المحاولات فعليًا بعد اعتماد 140 ورقة، وتشغيل محفزات التزامن الأصلية.
- تزامن نشر/تراجع حقيقيين، وكشف إعادة الطلب بعد الحذف الكامل للجلسة.
- تأكيد صلاحيات Supabase الفعلية دون اتصال بالإنتاج.

أثبتت اختبارات الرفض أن هذه العمليات لا تكتب بيانات عند نقص التعريفات.

## الملفات والنسخة المحفوظة

- المصدر المرحّل: `qa/omr/development/source/`
- SQL المرحّل: `qa/omr/development/manual-review-repairs.sql`
- واجهة التطوير: `qa/omr/development/frontend/`
- قاعدة الاختبار والواجهة المحلية: `qa/omr/sql/preview.py` و`qa/omr/integrated-server.ts`
- أدلة SQL: `qa/omr/results/sql/sql-evidence.json`
- أدلة الدفعة والمتصفح: `qa/omr/results/integrated/`
- حزمة الإصدار التطويري وبصماته: `qa/omr/releases/`

ناقل الاختبار المحلي وسياق المراجع الاصطناعي **ليسَا مصادقة إنتاجية** ولا يجوز شحنهما.
ملفات الإنتاج الحالية ونسخة GitHub الأصلية محفوظة؛ لم تُعدّل درجات أو بيانات حقيقية.

## التشغيل وإعادة التحقق

```sh
python3 -u qa/omr/sql/preview.py
bun test --timeout 180000 qa/omr/*.test.ts
python3 qa/omr/sql/batch.py
node qa/omr/ui-integration.mjs
```

اختبار المتصفح يحتاج جلسة جديدة من برنامج المعاينة؛ لأنه ينفذ تعديلًا اصطناعيًا مسجلًا على أول ورقة.
قاعدة البيانات مؤقتة، تستخدم socket خاصًا دون TCP ولا ترث إعدادات اتصال إنتاجية.
إيقاف المعاينة يوقف خادم القاعدة؛ تبقى ملفات الاختبار الاصطناعية تحت `/tmp` فقط إلى أن ينظفها النظام.

## خطة نشر وتراجع آمنة — لم تُنفذ

1. **بوابة منع النشر:** لا تطبيق لـ SQL المرحّل ولا نشر Edge حتى اكتمال التعريفات والاختبارات المحجوبة.
2. تركيب التعريفات الأصلية كاملة في قاعدة اختبار اصطناعية، دون حذف FK أو تعطيل محفز.
3. اختبار النشر والتراجع المصرحين والتزامن والحقن المتعمد للفشل؛ يجب ألا تبقى نتائج جزئية.
4. تجهيز واجهة الإنتاج من الصفحة الحالية بإضافة لوحة المراجعة، لكن باستعمال `teacher-access.js` الحقيقي بدل `local-transport.js`. منع إدراج قاعدة المعاينة وسياقها الاصطناعي في حزمة الإنتاج.
5. قبل النشر المصرح: حفظ نسخة مصدر Edge المنشورة وتعريفات SQL والصلاحيات الحالية ونسخة احتياطية وفق سياسة المشروع. لا يُفترض أن نسخة GitHub الأقدم بديل آمن.
6. تطبيق تغيير SQL داخل معاملة، ثم Edge والواجهة المتوافقين مع بروتوكول السبب والإصدار الجديد، بعد موافقة صريحة.
7. إذا فشل التطبيق داخل المعاملة، يُلغى تلقائيًا؛ لا حذف يدوي لدرجات.
8. إذا ظهر خلل بعد التشغيل: إيقاف نشر النتائج والتراجع الإداري أولًا، والإبقاء على سجلات التعديل والدرجات. إعادة آخر إصدار متوافق ومختبر من الواجهة وEdge، لا النسخة القديمة التي تسقط سبب التعديل.
9. لا حذف لأعمدة التدقيق أو الجداول أو سجلات التعديل، ولا `TRUNCATE` في الإنتاج، ولا عكس درجات فعلية تلقائيًا. أي استعادة بيانات تحتاج موافقة منفصلة وخطة تعتمد على النسخة الاحتياطية.

**الخلاصة:** القراءة والحفظ والمراجعة المحلية وواجهة التطوير نجحت بالأدلة. النسخة محفوظة، لكنها **غير جاهزة للنشر** حتى إغلاق تبعيات النشر والتراجع الأصليين.
