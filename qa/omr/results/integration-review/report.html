# مراجعة تكامل معلّمي — نسخة التطوير المعزولة

**الحكم النهائي: غير جاهز للنشر.** تم إصلاح واختبار الدخول والحفظ والمراجعة محليًا، لكن لا يوجد اختبار إيجابي مكتمل لترحيل درجات أوراق التظليل إلى المحاولات، أو التراجع عن ذلك الترحيل بالمحفزات الأصلية.

لم يُعدّل Supabase أو GitHub Pages، ولم تُستخدم سجلات طلاب حقيقية. لا اتصال بقاعدة الإنتاج في هذه الاختبارات. تبقى النسخة السابقة المحفوظة مستقلة عن حزمة هذه المراجعة.

## ما دُمج بالفعل

- المصدر المرجعي ما زال نسخة `nafes-exam` المرفوعة من النشر؛ الإصلاحات في `qa/omr/development/source` وليست استبدالًا بمحرك GitHub الأقدم.
- التحقق من المعلم يقرأ جدول `nafes_teacher_access` الحقيقي التعريف، بعد تجزئة `x-teacher-key` والتحقق من النشاط. الصلاحية المفقودة أو غير المعروفة لا تصبح `all`.
- حدود مادة المراجعة تتحقق من كل المواد، مع معالجة مصفوفة مواد فارغة دون تجاوز نطاق المعلم.
- تعديل الجلسة وترحيل نتائجها يتطلبان المراجع المسجل؛ الحساب الرئيسي يستطيع الاطلاع الأوسع وفق المصدر، لكنه لا يستبدل مراجع الجلسة صامتًا.
- التراجع المدقق يتطلب حسابًا رئيسيًا نشطًا. أُصلحت حدود التفويض في SQL المرحّل لتتوافق مع وصول الحساب الرئيسي عبر المالكين، مع حفظ مالك المراجعة الأصلي عند إنشاء الاختبار؛ سجل التراجع يثبت الفاعل الإداري لا يفترض أنه مالك المراجعة.
- أضيفت دالة تفويض تطويرية واضحة `nafes_scan_actor_context`، وليست تعريفًا مختلقًا لدالة إنتاج مفقودة. اختُبرت بوابة تفويضها فقط، لا حذف المحاولات أو نشرها.
- مسارات حذف المحاولة ومسح اختبار أو مجموعة اختبارات لا تستطيع تجاوز حماية نتائج أوراق المراجعة وسجل التراجع.
- معاينة الواجهة تستدعي `handleAssessments` الفعلي ثم معالج الأوراق وSQL المحلي، بدل تمرير هوية معلم جاهزة مباشرة إلى معالج الأوراق. مفتاح المعاينة اصطناعي عام للاختبار فقط.
- جلب الجداول والحفظ في النسخة المصححة يعملان بدور `service_role`، لا بمالك PostgreSQL. تركيب المخطط الأصلي افتقد ACL جداول التصحيح؛ أضيفت منح تطويرية صريحة محدودة على الجداول الست المعروفة، دون منح للأدوار العامة أو تعطيل RLS. لا يعني ذلك أن ACL الإنتاج معطلة أو مطابقة لهذه المنح.
- بقيت الإجابات غير المحسومة محجوبة، وسبب التعديل إلزاميًا، وسجل التعديل محفوظًا، وإعادة القراءة اقتراحًا لا تمحو التصحيح اليدوي.

اختلافات مقارنة المصدر الأصلي الأربعة: فقد سبب التعديل من سجل SQL، السماح لحساب رئيسي آخر بتعديل جلسة ليست له، حفظ تعديل دون سبب، وتحويل صلاحية غير معروفة إلى حساب رئيسي. كانت مقارنة منطق الأصل بمالك PostgreSQL لأن صلاحيات جداول المسح الأصلية لم تُصدّر؛ نسخة الإصلاح اختُبرت بدور الخدمة مع منح التطوير المعلنة. لا نستخدم هذا الاختلاف لإثبات عطل ACL إنتاجي.

## العوائق الحقيقية التي لم تُغلق

1. **`nafes_scan_deletions`:** تعريف الجدول الأصلي وأعمدته وقيوده وفهارسه وسياساته وصلاحياته ومحفزاته. الحقول التي تستخدمها دالة الحذف لا تكفي لإعادة تكوينه بأمان.
2. **`nafes_assessments` و`nafes_students`:** تعريفات الأصل المنشور الأحدث مع العلاقات والقيود والمحفزات والسياسات والصلاحيات. تعريف `nafes_assessment_attempts` الموجود يحيل إليهما ولا يغلق التبعيات وحده.
3. **`lugati_sync_sections_attempt` و`lugati_sync_student_worksheets`:** التواقيع والأجسام وتبعياتهما الفعلية؛ محفزات المحاولات الأصلية تستدعيهما. لم تُعطّل أو تُستبدل.
4. **ACL وسياسات جداول المسح الأصلية:** المنح التطويرية معلنة وليست إثباتًا لاكتمال تصدير صلاحيات الإنتاج. اختبار PostgreSQL المحلي ليس اختبار بوابة Supabase/PostgREST المنشورة.

ربط `sheet_id` و`answer_version` و`scan_session_id` بالمحاولة والحفظ الذري والتراجع المدقق موجود في كود التطوير، لكن **نجاحه الإيجابي في SQL غير مثبت** إلى أن تُركب هذه التبعيات الأصلية. إنشاء الدوال في PostgreSQL لا يثبت صلاحية جميع أوامر أجسامها المؤجلة. اختبارات الرفض الناجحة لا تثبت إنشاء المحاولة أو حذفها واستعادتها.

لا يوجد أساس آمن لاعتبار المهمة مكتملة أو للنشر. لم نُنشئ جداول بديلة، ولم نخمن أجسام الدوال المفقودة، ولم نعتمد درجات أوراق قديمة.

## خطة التراجع الآمنة قبل أي نشر مستقبلي

1. لا نشر لهذه النسخة ما دامت العوائق أعلاه قائمة؛ الحزمة للمراجعة فقط.
2. عند اكتمال التبعيات، تُختبر دورة إيجابية: حفظ → إنشاء محاولة → إعادة الطلب دون تكرار → تراجع إداري مع سجل كامل → رفض فاعل غير مصرح، مع المحفزات الأصلية.
3. قبل موافقة النشر: حفظ المصدر المنشور وتعريفات الدوال والقيود وACL الفعلية وإعدادات الدالة، ومراجعة فروق SQL. لا نفترض أن عكس SQL الحالي يعيد ACL مجهولة.
4. تفعيل التغيير تدريجيًا؛ عند خلل تُوقف عمليات الترحيل الجديدة ويُعاد المصدر السابق وفق موافقة النشر. لا تُحذف سجلات المراجعة، ولا تعاد درجات الطلاب آليًا، ولا يُستخدم عكس ملف الإصلاح كتراجع أعمى.
5. تراجع بيانات التصحيح مستقل عن تراجع الكود، ويتطلب آلية مدققة مثبتة وموافقة صريحة؛ لم تنفذ هنا على إنتاج أو بيانات حقيقية.
