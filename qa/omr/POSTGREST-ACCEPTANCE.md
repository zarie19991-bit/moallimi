# قبول تكامل HTTP/PostgREST — إصلاح مثبت وبوابة نشر مغلقة

## النتائج

- شُغّل **PostgREST 13.0.0 الحقيقي** أمام PostgreSQL 17.6 المعزول.
- **31 تحققًا ناجحًا، صفر فشل** في الجولة النهائية، مع 93 طلب REST مسجلًا من مسار التطبيق.
- **155 اختبار انحدار ناجحًا، صفر فشل، 1166 assertion** بعد تعديل التطبيق.
- لم تُعد دورة SQL السابقة ذات 46 تحققًا؛ أُعيد استخدام تركيب مخططها الأصلي، لا نتائجها بوصفها دليل HTTP.
- بيانات اصطناعية فقط، وأسرار JWT محلية مؤقتة، ومقبس PostgreSQL خاص وHTTP على loopback فقط.

## العطل الفعلي والإصلاح

كان `teacher_paper_review_save` يحفظ محاولات ودرجات صحيحة، لكنه يبني `rendered_sections` دون `outcome` و`indicator` الرقمي. لذلك لم تجد محفزات المزامنة الأصلية مؤشرًا صالحًا، فبقي جدول النتائج التابعة فارغًا.

الفشل قبل الإصلاح:

```text
AssertionError: edge_rendered_indicators_feed_original_adaptive_trigger: {'observed_count': 0}
```

أضيف الحقلان من سجل FRAMEWORK الموثوق، لا من مدخل المعلم. ملف الإصلاح: `qa/omr/development/source/assessments.ts`.

الدليل قبل الإصلاح: `results/postgrest/before.json`.
الدليل بعده: `results/postgrest/evidence.json`.

## الدورة المثبتة

1. استعلام الخدمة عبر REST الحقيقي 200.
2. مفتاح معلم مفقود/خاطئ/غير نشط: 401.
3. مادة غير مصرح بها أو مراجعة مملوكة للغير: 403/404 حسب مسار إخفاء المورد.
4. إجابة ambiguous: رفض الاعتماد 409.
5. تعديل بلا سبب: رفض 400؛ تعديل مع سبب: 200 وسجل تدقيق قابل للاسترجاع.
6. إعادة قراءة صورة اصطناعية: 200 وproposal_only، مع بقاء الإجابات اليدوية.
7. التحقق ثم إنهاء الدفعة: 200.
8. المتصفح أصدر طلبي اعتماد متزامنين من JavaScript الواجهة؛ مسار التطبيق الحقيقي عبر عميل PostgREST الرسمي حفظ محاولة واحدة بدرجة **10/10 و100%**، ثم أنشأ النتيجة التابعة.
9. إعادة الاعتماد: 200 دون ازدواج المحاولات.
10. معلم غير مشرف لمراجعة يملكها: رفض التراجع 403.
11. مشرف: تراجع 200 حذف المحاولة المستهدفة فقط وأبقى محاولة مستقلة **5/10 و50%**، وأعاد التجميع إليها.
12. حفظ تدقيق التراجع، ومنع الوصول المباشر المجهول إلى جدول المعلمين ورفض JWT غير صالح.
13. المتصفح حمّل صفحة الواجهة الفعلية وأصدر طلبًا من `NafesTeacher.api` إلى API، ثم REST، واسترجع سجل التراجع المحفوظ. لم يكن هذا اختبار نقر لجميع أزرار المنصة.
14. أُنشئ dump محلي خاص وأُعيد تركيبه في قاعدة معزولة ثانية؛ تطابقت الدرجة المتبقية وسجل التدقيق.

الحالة قبل الإصلاح كانت فشل ربط التحليل، لا فشل القارئ. لم يُبنَ محرك OMR بديل، ولم تُعد تجربة 140 صورة القديمة.

## الصلاحيات وحدود المطابقة

تستخدم الطلبات مفاتيح معلمين اصطناعية يحقق منها authenticator التطبيق الحقيقي، وJWT اختبار يقبله PostgREST الحقيقي. دور اتصال HTTP هو authenticator اختباري محدود العضوية إلى anon/authenticated/service_role، وليس postgres.

أُبقيت الجداول والقيود والمحَفزات والسياسات وACL المرفقة. ACL المخططات وpaper_reviews وscan RPC وخصائص أدوار الإنتاج غير مكتملة في الملفات؛ منح الإصلاح المحلية مسماة تطويرية، وليست ادعاء تطابق إنتاجي. إثبات المطابقة النهائية يحتاج قراءة metadata مخولة من وجهة الإنتاج.

## مقارنة الوجهة ومنع استبدال الأحدث

جُلب origin/main حديثًا للقراءة فقط. تطابق index وpaper-scan وomr-server مع المصدر المرفق، لكن assessments يختلف؛ ظهرت تغييرات حديثة في إعادة توزيع الاختيارات. لم يُدمج الفرع أو تُستبدل نسخة الإنتاج بملف QA.

بصمات المصادر ونسخة GitHub وفحص الصفحة الحية 200 محفوظة في `destination-check.json`. ذلك **فحص أساس قبل النشر**، لا اختبار ما بعد النشر. أحدث مصدر Supabase المنشور لم يُسترجع لأن قناة الإدارة المخولة غير متاحة.

## عائق الإطلاق الواحد

**عدم توفر قناة إدارة ونشر مُثبتة الصلاحية إلى الوجهة الأصلية.**

- اتصال GitHub مفعّل على الحساب، لكن gh يعيد طلب تسجيل الدخول وحق كتابة المستودع لم يُثبت؛ محاولة push --dry-run انتهت بمهلة ولم تنشئ فرعًا.
- لا اتصال إدارة Supabase في البيئة ولا `SUPABASE_ACCESS_TOKEN`.
- لا `GH_TOKEN` للـCLI/API هنا.

المطلوب: تفويض آمن لإدارة المستودع الأصلي ومشروع Supabase الأصلي، باستخدام الاتصال المفعّل أو أسرار نشر مخولة. لا مفاتيح معلمين أو service keys خاصة بالطلاب مطلوبة.

**لم يُنشر شيء.** لا نقل إلى Replit كبديل. لم تُنشأ نسخة احتياطية للإنتاج أو تُقرأ سجلاته؛ نسخة الاستعادة التي اختُبرت اصطناعية محلية فقط.

## خطة نشر وتراجع محفوظة

1. بالوصول المخول: قراءة أحدث ملفات Edge وACL ونسخة GitHub Pages، ثم إعادة التوفيق مع التغييرات الحديثة دون الاستبدال الكامل.
2. حفظ إصدار الشيفرة وتعريفات SQL/ACL الحالية في مخزن خاص، والتأكد من نسخة استعادة إنتاجية مخولة، دون تنزيل بيانات طلاب إلى Replit.
3. استكمال مطابقة صلاحيات البيئة المعزولة وتشغيل بوابة التكامل على المرشح المدمج.
4. نشر الإصلاح الضيق إلى nafes-exam والمستودع الأصلي فقط؛ لا تشغيل مسار كتابة درجات اصطناعية في الإنتاج.
5. التحقق من الإصدار والرابط والأصول وطلبات القراءة/الرفض الآمنة.
6. عند فشل الإطلاق: وقف اعتماد الدفعات، وإرجاع شيفرة Edge وملفات Pages وتعريفات الإجراءات الموثقة فقط. **لا استعادة قاعدة كاملة فوق درجات أحدث ولا حذف نتائج للعودة لإصدار شفرة قديم.**
7. التراجع عن تصحيح منشور عملية منفصلة: عبر مسار المشرف المدقق وبمعرفات مستهدفة فقط، وليس ضمن rollback إصدار البرنامج.

ملفات `last-failure.json` وسجل before تاريخية؛ الحكم الحالي يعتمد على evidence النهائي ذي 31 نجاحًا.
