# قبول دورة محاولات OMR والتراجع — محليًا

## النتيجة

**نجحت دورة الحفظ والتراجع الإيجابية في PostgreSQL المحلي. لم يحدث نشر إنتاجي.**

- **46 تحققًا SQL ناجحًا، صفر assertions فاشلة.**
- **155 اختبار انحدار ناجحًا، صفر فشل، 1166 assertion عبر 12 ملفًا.**
- لا تُضاف إليها أعداد الاختبارات السابقة المتداخلة.
- لم تُعد تجربة الصور الـ140. الدليل الجديد يختبر ورقة اصطناعية بأربع إجابات ومحاولة مستقلة أقدم، وليس نشر 140 محاولة.

## مصدر الإصلاح

جُلب أحدث فرع المراجعة `qa/omr-catalog-locked-20261009` دون checkout أو merge لتغييراته.

فُكت `production-schema-publish-unblock.pgp.base64` بالمفتاح الموجود في الأسرار. كما أُعيد فتح الحزمتين السابقتين للاستيراد من التعريفات الأصلية فقط. جميع ملفات plaintext بقيت في مسارات `/tmp` خاصة وغير مرفقة بحزمة التسليم.

لم يُعدّل محرك OMR أو منطق الإصلاح التنفيذي. التغيير الفعلي هو دعم تركيب المصدر الجديد في بيئة الاختبار:

- `auth.users.confirmed_at`: التوليد STORED كما ورد، بدل تفسير التعبير كـDEFAULT.
- `nafes_analysis_exclusion_audit.id`: هوية ALWAYS، مع اسم التسلسل وخياراته وACL الأصلية.
- وظائف `auth` و`private` والوظائف الست العامة الإضافية: بأجسامها الأصلية.
- الجداول والمحَفزات والفهارس وRLS وACL المرفقة، بما في ذلك فهرس بنك الأسئلة الذي كان يفشل.
- لم تُعطّل قيود أو محفزات، ولم تُستبدل دوال الإنتاج بنماذج مبسطة.

## الإثبات الإيجابي

| المرحلة | النتيجة |
|---|---|
| إنشاء الطالب | اجتازت الدالة الأصلية للتطبيع ومحفزات الطالب |
| إجابة ambiguous | رفض الاعتماد قبل الحسم |
| مراجعة يدوية | حُفظ السبب داخل سجل التعديل وزاد answer_version |
| اعتماد الورقة والدفعة | نجح بعد الحسم |
| طلبا نشر أوليان متزامنان | كلاهما نجح، مع محاولة واحدة فقط |
| الربط | student_id والنموذج A والاختيارات مطابقة للورقة |
| الدرجة | score=4، total=4، percent=100 |
| المزامنة الأصلية | أنشأت enrichment ومصدرها هو محاولة الطالب |
| إعادة النشر المتزامنة | لا ازدواج، ولا تغير في لقطة المحاولة |
| منع تعديل درجة المحاولة المقدمة | المحفز الأصلي رفض التعديل |
| التراجع غير المخوّل | رُفض دون حذف أو سجل جزئي |
| إلغاء معاملة التراجع عمدًا | عادت المحاولات والورقة والمراجعات والنتيجة التابعة كاملة |
| التراجع المخوّل | حذف المحاولة المرتبطة بالورقة فقط |
| حماية النتائج الأخرى | بقيت المحاولة الأقدم ودرجتها 2/4 و50% |
| إعادة التجميع | المحفز الأصلي أعاد مصدر النتيجة إلى المحاولة الأقدم، وتصنيفها remedial |
| سجل التراجع | احتفظ بالمحاولة المحذوفة وسبب المراجعة، ولم ينسخ access_hash |
| تكرار التراجع | replay مع سجل واحد، دون محو المحاولة الأخرى |
| RLS الأصلي للفصول | أظهر فصل المالك فقط ومنع الإدخال لمالك آخر |
| auth.uid والمحَفز الخاص | نجحت القيمة الافتراضية للمالك وتحديث updated_at |
| عمود auth المولّد وتدقيق الاستبعاد | نجحا بالتوليد والهوية الحقيقيين |

اختبار الإلغاء المتعمد هو RPC تراجع ناجح داخل معاملة، ثم `SELECT 1/0` قبل COMMIT. هذا يثبت إلغاء آثار التراجع ومزامنته معًا عند فشل المعاملة، ولا يُوصف بأنه فشل نشر إنتاجي.

## الأدلة وإعادة التنفيذ

الدليل: `qa/omr/results/publish-unblock/evidence.json`، ويتضمن بصمات SHA-256 للمصادر الثلاثة.

الاختبار يستخدم PostgreSQL 17.6 بمقبس Unix خاص، دون TCP أو إعدادات اتصال إنتاجية. roles وclaims اصطناعية؛ لا مفاتيح معلمين حقيقية.

```sh
OMR_PRIVATE_CATALOG=/tmp/private/catalog.json \
OMR_PRIVATE_DEPENDENCIES=/tmp/private/dependencies.json \
OMR_PRIVATE_UNBLOCK=/tmp/private/publish-unblock.json \
python3 qa/omr/sql/dependencies-integration.py
```

المسارات أعلاه أمثلة؛ يجب الإشارة إلى الملفات الأصلية المفكوكة خارج المستودع. لا حاجة لإعادة استخراج التعريفات اللازمة لهذه الدورة أو اختراع SQL.

اختبارات الانحدار:

```sh
bun test qa/omr/*.test.ts
```

## حكم الجاهزية وحدود الاختبار

**العائق السابق لإنشاء المحاولات والتراجع عنها أُغلق محليًا.**

**لم تتحقق جاهزية النشر الإنتاجي بعد:** هذه الجولة native SQL، وليست طلبات فعلية عبر PostgREST/Supabase. ACL المخططات و`nafes_paper_reviews` وscan RPC وخصائص/عضويات أدوار الإنتاج لم ترد كاملة؛ لا تُقدّم صلاحيات scaffolding المحلية كإثبات تطابق إنتاجي.

السياسات والصلاحيات التي وردت في الحزم جرى تركيبها واختبار الأجزاء المذكورة منها، دون تخفيفها. إن نجاح دورة النشر هنا لا يثبت فروع بنك التدريب أو كل وظائف منصة معلّمي غير الداخلة في هذه الدورة.

المعاينة الحالية بقيت معزولة، لكنها ليست مربوطة بقاعدة هذا الاختبار المؤقتة، ولا تعرض تجربة حفظ المحاولات الجديدة من الواجهة. لم تتغير ملفات الواجهة في هذه الجولة.

تبقى بوابة إطلاق الإنتاج: إثبات مسار API/الواجهة والصلاحيات المقابلة في بيئة آمنة، ثم التحقق من النسخة المستهدفة والنسخة الاحتياطية وخطة الاستعادة. لا نشر إلى Supabase أو GitHub Pages أو موقع آخر.
