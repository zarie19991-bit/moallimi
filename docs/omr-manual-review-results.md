# اختبارات الحفظ والمراجعة — نطاق محلي معزول

## الحدود

سمح المستخدم بقاعدة SQL اختبار محلية مؤقتة ومعزولة ببيانات اصطناعية فقط. لم تُنشأ بعد:
تعريفات SQL الأصلية غير موجودة محليًا، ولا يجوز اختراع مخطط بديل.
لم يحدث اتصال بإنتاج Supabase، أو قراءة بيانات طلاب، أو كتابة درجات، أو نشر.

الاختبارات الحالية تستعمل كائنات JavaScript لتسجيل حدود الاستدعاء وتحديث اللقطات.
مسجل RPC يتوقف باستثناء قبل تنفيذ SQL ولا يحاكي نجاح الحفظ. لذلك نجاح هذه
الاختبارات لا يثبت التزام القيود أو المحفزات أو المعاملات في قاعدة البيانات.

## الإصلاحات في نسخة التطوير الحالية

- التحقق من الورقة يرفض الإجابات غير المحسومة ورقم النسخة القديم قبل RPC، بنفس
  اسم الاستدعاء ومعاملاته التي كانت موجودة في المصدر.
- تعيين الهوية لا يرقّي إجابة سبق أن كانت uncertain إلى correct/incorrect.
  الاختيارات والتظليل وبيانات المراجعة البشريّة محفوظة، وقد تكون القراءة clear
  بينما لا يزال الحكم uncertain بانتظار مراجعة صريحة.
- إعادة معالجة ورقة بها مراجعة بشرية تحفظ اللقطة الحالية وعلامات المراجعة.
  القراءة الجديدة اقتراح غير مطبق داخل JSON، لا درجات جديدة ولا بديل للمراجعة.
  حتى فشل القارئ لا يمحو الإجابات اليدوية.
- الإنهاء وتجهيز النتائج يفحصان كل الأوراق غير المحجوبة بسبب التكرار؛ لا يجري
  تجاهل ورقة معلّقة لأنها ليست verified. سلامة التحقق الذري داخل SQL ما تزال غير مثبتة.

## المتطلبات غير المكتملة

- حفظ الإجابة الغامضة دون ترقيتها داخل SQL نفسه.
- تسجيل التعديل اليدوي وتغيير الهوية وسبب كل تعديل داخل سجل تدقيق حقيقي.
- عدم تكرار التسجيل أو الاعتماد، وتعارض طلبات الحفظ والمراجعة المتزامنة.
- أثر محفزات SQL على اللقطات المحفوظة وعلامات المراجعة أثناء إعادة المعالجة.

لم يُخترع معامل p_reason: استدعاء التعديل الحالي لا يمرّر السبب. يلزم توقيع
وظيفة SQL الأصلي وجسمها لمعرفة كيف يُضاف أو يُستخدم السبب بشكل متوافق.

## المصدر المطلوب بالضبط

الجداول التي حددها المستخدم:

- nafes_scan_sheets
- nafes_scan_sessions
- nafes_scan_answer_edits
- nafes_scan_identity_edits
- nafes_scan_alerts

يلزم تعريف الأعمدة وأنواعها وقيمها الافتراضية والقيود والفهارس وسياسات RLS
والمحفزات ووظائف المحفزات، ثم تعريفات RPC الفعلية المشار إليها في المصدر:
nafes_scan_register، nafes_scan_assign_identity، nafes_scan_edit_answer،
nafes_scan_verify_current، nafes_scan_finish، nafes_scan_delete_corrections.
هذه أسماء من كود Edge فقط، لا تأكيد بأنها موجودة في الإنتاج بنفس التواقيع.
أي أنواع أو جداول أو دوال مساعدة تشير إليها التعريفات الأصلية يلزم تصديرها أيضًا.

ملف القراءة الاختياري للمالك:
`qa/omr/export/manual-review-metadata-readonly.sql`.
لم يُنفذ؛ يقرأ بيانات تعريف المخطط لا صفوف الطلاب أو النتائج. على المالك مراجعة
المصدر الناتج وإزالة أي أسرار مضمّنة قبل مشاركته.

## إعادة التحقق

```sh
npm run test:omr:manual-review
```

المخرجات في `qa/omr/results/manual-review/`:
report.html، evidence.json، validation.log.
توضح البصمة والأعداد الحالية والمقارنة الأصلية/الإصلاح وSQL_executed=false.
تظل اختبارات SQL المعلّقة منفصلة عن الناجحة. لا تبدأ مرحلة واجهة المعلم أو
يُعلن نجاح المهمة كاملة قبل سد فجوة المصدر والتحقق من التخزين الحقيقي.
