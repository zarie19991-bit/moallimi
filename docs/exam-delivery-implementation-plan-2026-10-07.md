# خطة تنفيذ استقرار تسليم الاختبارات

**التاريخ:** 7 أكتوبر 2026  
**النطاق:** منصة معلّمي الحالية دون إعادة بناء.

## 1. الهدف التشغيلي

الوصول إلى تصميم يتحمل انقطاع الشبكة المؤقت، فقد استجابة HTTP بعد نجاح الخادم، وضغط الذروة دون فقد الإجابات أو إنشاء تسليمات نهائية مكررة.

## 4. الموارد المطلوبة

### الحد الأدنى

- مهندس واحد يمتلك صلاحية GitHub + Supabase.
- معلم/مشرف واحد للتحقق من تجربة الطالب.
- جهازان أو ثلاثة لاختبار:
  - حاسب مكتبي/محمول.
  - هاتف.
  - متصفح ثانٍ لمحاكاة استعادة الجلسة.
- بيئة Staging لاختبار الحمل الحقيقي قبل أي تجربة 500+ اتصال.

### لا يلزم حاليًا

- خادم تطبيقات جديد.
- Kubernetes.
- تطبيق جوال مستقل.
- Queue خارجي للتسليم.
- CDN إضافي للصفحات الثابتة.

## 5. خطة اختبار Staging

### المرحلة A — 100 مستخدم متزامن
- start → 15 save cycles → finish.
- المدة 10 دقائق.
- القبول: p95 < 2 ثانية للحفظ، 0 duplicate submissions.

### المرحلة B — 500 مستخدم
- Ramp up تدريجي خلال دقيقتين.
- 10% من الطلبات تحاكي تأخيرًا 1–3 ثوان.
- القبول: 5xx < 0.5%، كل retries تتعافى أو تظهر كPending.

### المرحلة C — 1,000 مستخدم Burst
- دخول كثيف في دقيقة واحدة.
- لا يستخدم الإنتاج لهذا الاختبار.
- القبول: لا سقوط بيانات؛ إن ارتفع p95 يتم قياس نقطة الاختناق قبل رفع الموارد.

### المرحلة D — Network Chaos
- Offline 60–90 ثانية لـ20% من العملاء.
- فقد response بعد server commit لجزء من finish.
- القبول: Local Draft يحتفظ بكل الإجابات، وإعادة finish لا تنشئ سجلًا ثانيًا.

## 6. مؤشرات قرار التوسع

لا يرفع مستوى البنية التحتية إلا إذا تحقق واحد أو أكثر بشكل متكرر:

- p95 > 2 ثانية لعشر دقائق أو أكثر.
- 5xx/52x > 0.5% لمدة 10 دقائق.
- Queue/Pending يرتفع رغم اتصال العملاء.
- Postgres يظهر زمن استعلام/قفل هو عنق الزجاجة.
- Edge capacity أو region routing يثبت أنه السبب من السجلات.

عندها يكون الترتيب:
1. تحسين الاستعلامات والفهارس.
2. تخفيف payloads.
3. فصل الأعمال غير الفورية عن مسار التسليم.
4. مراجعة Region/Capacity/plan.
5. فقط بعدها التفكير في بنية إضافية.

### تراجع Backend

- اترك جدول telemetry قائمًا؛ وجوده بلا كتابة لا يؤثر على الاختبارات.

### تراجع Recovery Grace
إذا كانت سياسة الجهة لا تسمح به:
- يعاد شرط انتهاء الوقت إلى الاعتماد على آخر نسخة خادمية.
- يجب إدراك أن هذا يخفض قدرة استرداد الإجابات التي ظلت محليًا وقت الانقطاع.

## 8. تعريف النجاح

تعد الميزة مقبولة عند تحقق كل الآتي:

- CI ناجح.
- Chaos Simulation: 0 lost answers و0 duplicates.
- صفحات الطالب تعرض تعليمات التعافي الصحيحة.
- التسليم القديم المكرر يعيد success لا 409.
- إيصال التسليم يظهر بعد اعتماد الخادم.
- لوحة المراقبة تعمل حسب نطاق المعلم.
- لا يوجد تحذير أمني جديد على جدول telemetry.
- أول نافذة إنتاج حقيقية لا تظهر ارتفاعًا جديدًا في 5xx أو p95.
