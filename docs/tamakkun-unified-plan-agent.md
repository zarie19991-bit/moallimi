# الخطة الموحدة والوكيل التكيفي — مِنَصَّةُ تَمَكُّن

## الهدف
تجميع نتائج الاختبارات المتعددة للطالب في **الرياضيات والعلوم** داخل وثيقة واحدة، ثم تحويل كل مؤشر إلى مسار علاجي أو تعزيز أو إثراء دون إنشاء أوراق منفصلة لكل اختبار.

## مصدر البيانات
الوكيل يقرأ القياسات المسجلة فعليًا من:
- `nafes_assessment_attempts`
- `nafes_simulation_attempts`
- `nafes_exam_attempts`

لا ينشئ مؤشرًا أو نتيجة لطالب لم يختبر، ولا يستخدم نتائج المسابقة بوصفها بديلًا عن قياس الإتقان الرسمي.

## قاعدة التشخيص التراكمي
لكل طالب + مادة + ناتج تعلم + مؤشر:
1. تجمع جميع القياسات المتاحة لذلك المؤشر.
2. تجمع الإجابات الصحيحة وعدد الأسئلة القابلة للتصحيح.
3. **درجة التشخيص = مجموع الصحيح ÷ مجموع الأسئلة × 100**.
4. يحتفظ النظام بصورة مستقلة بـ:
   - أحدث نتيجة.
   - النتيجة السابقة عند توفرها.
   - مقدار الاتجاه بين آخر قياسين.
   - أفضل نتيجة.
   - عدد القياسات وعدد الأسئلة التي استند إليها القرار.

هذا يمنع اختبارًا قصيرًا جدًا من مساواة اختبار أكبر في الوزن، وفي الوقت نفسه لا يخفي التحسن الأخير لأن «أحدث نتيجة» و«الاتجاه» يظهران بجانب التشخيص.

## المسارات
| درجة التشخيص | المسار | الهدف |
|---|---|---|
| أقل من 70٪ | علاجي | إعادة بناء المفهوم وتدريب موجه |
| 70٪ إلى أقل من 90٪ | تعزيز | تثبيت التطبيق والانتقال إلى استقلالية أعلى |
| 90٪ فأعلى | إثرائي | مواقف أعلى تفكيرًا وتبرير/تفسير |

الإجراء ليس نصًا عامًا: يولد بحسب **المادة + نص المؤشر + المسار**. الرياضيات تستخدم مثالًا محلولًا/مسائل متدرجة/استراتيجية، والعلوم تستخدم رسمًا أو نموذجًا/بيانات أو تجربة/دليلًا علميًا.

## التزامن التلقائي
`lugati-adaptive-plan` يحافظ على أسماء العمليات السابقة حتى لا تنكسر الواجهات. عند مزامنة الطالب أو لوحة المعلم:
- يعاد حساب التشخيص من سجل القياسات.
- يحدث `lugati_adaptive_assignments`.
- إذا وصل قياس أحدث يعاد تعيين المسار حسب التشخيص الجديد.
- يبقى سجل محاولات التدريب في `lugati_adaptive_training_attempts`.
- رحلة الإتقان وسجل الطالب يظلان مصدر متابعة النشاط بعد الإرسال.

## واجهات API الجديدة
- `student_unified_plan`: خطة الطالب نفسه فقط.
- `teacher_unified_plan`: خطة طالب محدد مع احترام نطاق مادة حساب المعلم.
- `teacher_unified_overview`: عدادات علاج/تعزيز/إثراء للرياضيات والعلوم مبنية على التشخيص نفسه.

المصادقة هي جلسة تَمَكُّن الحالية. لا يقبل الخادم `student_id` من طالب لقراءة طالب آخر.

## تصميم الورقة
الملفات:
- `tamakkun-unified-plan.js`
- `tamakkun-unified-plan.css`

الوثيقة تشمل:
- بيانات الطالب.
- ملخص عدد المؤشرات العلاجية/التعزيزية/الإثرائية.
- شرح أساس القرار.
- قسم الرياضيات وقسم العلوم في **المستند نفسه**.
- لكل مؤشر: عدد القياسات، عدد أسئلة الدليل، الاتجاه، التشخيص، أحدث نتيجة، المسار، الإجراء المخصص، معيار الانتقال.
- زر **طباعة / حفظ PDF** باستخدام طباعة المتصفح مع `print-color-adjust: exact`.

الألوان هادئة ومتباينة، ويستخدم `:focus-visible` ودعم `prefers-reduced-motion` للمساعدة في متطلبات WCAG.

## استخدام المعلم
1. افتح تَمَكُّن → العلاج والإثراء.
2. اضغط «الخطة الموحدة للرياضيات والعلوم».
3. اختر الطالب.
4. راجع الأدلة والمسار لكل مؤشر.
5. اطبع أو احفظ PDF عند الحاجة؛ لا توجد حاجة لطباعة ورقة مستقلة لكل مؤشر.

## استخدام الطالب
يظهر زر «خطتي الموحدة» في مساحة الطالب. لا يعرض إلا بيانات الطالب صاحب الجلسة، ويحدث محتواه من القياسات المسجلة عند فتحه.

## المسابقة
لم يُستبدل محرك المسابقة المستقر. أضيف `tamakkun-competition-polish.css` لتحسين:
- وضوح المؤقت والـHUD.
- التقدم والمحطات.
- حجم مناطق الاختيار على الجوال.
- التركيز بلوحة المفاتيح.
- تقليل الحركة عند تفعيل إعداد النظام.
- الحفاظ على ألوان تَمَكُّن بدل ألوان متنافرة.

اختبارات الاعتمادية السابقة تبقى المرجع للمنطق: ربط الإجابة بالسؤال، منع التكرار، قفل الخيارات بعد الإجابة، سلامة الوسائط، ومعاينة النص والتقرير.

## الخصوصية
- لا يضاف مفتاح خدمة إلى المتصفح.
- الاستعلامات ذات الصلاحية المرتفعة تبقى داخل Edge Function.
- كل طلب يمر عبر فحص جلسة `lugati_sessions` وحالة الطالب/المعلم.
- حساب المعلم محدود بـ `subject_scope`.
- الورقة الرقمية لا تحفظ نسخة إضافية من أسماء الطلاب في جدول جديد؛ تُبنى لحظيًا من البيانات المصرح بها.
- لا توجد خطط افتراضية لطالب بلا نتيجة.

## الاختبار
`qa/tamakkun-unified-plan-unit.cjs` يتحقق من:
- الحدود الثلاثة 70/90.
- استبعاد القراءة من الورقة الموحدة.
- وجود إجراء مرتبط بنص المؤشر.
- عدادات الملخص.
- وجود مسارات API الجديدة.
- عقدة الطباعة ودمج الواجهة.
- إمكانية تحويل TypeScript إلى JavaScript في Node 24.

كما يستمر `qa/competition-unit.cjs` لاختبارات المسابقة الحالية.

## حدود حالية مقصودة
التشخيص يجمع **القياسات المتاحة في قاعدة البيانات** لأن المحاولات الحالية لا تحمل مفتاح فصل دراسي موحدًا على كل المصادر. عند اعتماد فصل/فترة موحدة في جميع الاختبارات يمكن إضافة مرشح زمني دون تغيير بنية الورقة.
