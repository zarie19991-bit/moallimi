# تمكّن UX v3 — إعادة تصميم التفاعل والاحتفاظ

## 1. أهداف التصميم
يركز الإصدار v3 على ثلاث نتائج قابلة للقياس:
1. تقليل زمن وصول الطالب لأول نشاط مفيد.
2. زيادة نسبة بدء المهام ثم إكمالها.
3. رفع العودة المتكررة للمنصة دون الاعتماد على إشعارات مزعجة أو نقاط وهمية.

القرارات البصرية أو التفاعلية لا تُعد نجاحًا بذاتها؛ النجاح يقاس بالسلوك الفعلي.

## 2. Personas

### أ. طالب يحتاج دعمًا
- يدخل غالبًا بعد اختبار منخفض.
- لا يريد قراءة تعليمات طويلة.
- أهم سؤال لديه: «ماذا أفعل الآن؟».
- نقطة الألم: كثرة الأقسام أو عدم معرفة النشاط المناسب.

### ب. طالب قريب من الإتقان
- يحتاج تثبيت المهارة لا إعادة شرح كامل.
- دافعه: رؤية تحسن واضح وإنجاز سريع.
- نقطة الألم: تكرار أنشطة لا تناسب مستواه.

### ج. طالب متقن
- يحتاج تحديًا أعلى حتى لا يشعر أن المنصة سهلة.
- دافعه: الإثراء والمنافسة والإنجاز.
- نقطة الألم: غياب تحديات واضحة بعد الإتقان.

### د. المعلم
- يريد معرفة من استجاب، ومن لم يبدأ، ومن تحسن.
- نقطة الألم: الانتقال بين شاشات متعددة للوصول للمعلومة.

## 3. تدقيق الواجهة السابقة

| المشكلة | الأثر | المعالجة في v3 |
|---|---|---|
| أول شاشة للطالب كانت رحلة مباشرة بلا ملخص يومي | الطالب لا يعرف الأولوية | إضافة «مسارك اليوم» والخطوة التالية |
| وجود كود قديم للرئيسية/مهامي/تقدمي رغم إلغاء هذه التبويبات | تعقيد تقني وإمكانية عودة مسارات متعارضة | حذف المسارات القديمة نهائيًا |
| حالة ثابتة «جاهز للتعلم» | لا تقدم معلومة | تحويلها لحالة ديناميكية بعدد المهام |
| شاشة الدخول تحمل كثيرًا من الرسائل والخيارات | حمل معرفي قبل الدخول | مهمة دخول واحدة + تفاصيل تجريبية مطوية |
| التحفيز غير موحد | صعوبة فهم التقدم | شارات مبنية على إنجازات فعلية |
| لا توجد قياسات UX دائمة | لا يمكن إثبات التحسن | إضافة أحداث UX محدودة وخصوصية عالية |

## 4. هيكل المعلومات

### الطالب
```
تسجيل الدخول
└── مساحة الطالب
    ├── الرحلات
    │   ├── مسارك اليوم
    │   ├── الخطوة التالية
    │   ├── ملخص الإنجاز
    │   ├── الشارات
    │   ├── تقدم المواد
    │   └── خريطة/رحلات المهارات
    ├── العلاج
    ├── تعزيز وإثراء
    └── المسابقات
```

تبقى الأقسام الأربعة التي سبق اعتمادها ثابتة. «مسارك اليوم» داخل الرحلات، وليس قسمًا خامسًا، حتى لا نعيد التعقيد.

### المعلم
```
لوحة المعلم
├── الرئيسية
├── المعلمون والأعمال
├── المسابقة
├── الخطط
├── تدريبات الطلاب
├── التحليل
└── التقارير
```

## 5. التصميم البصري
يستخدم v3 نظام الألوان الحالي للمنصة:
- Navy للبنية والعناوين.
- Teal للإجراء الأساسي والتقدم.
- Blue للمعلومات والتركيز.
- Amber للتحفيز المحدود.
- أخضر للإنجاز.
- أحمر للعلاج/الخطأ فقط.

قواعد إضافية:
- بطاقة واحدة = لون دلالي رئيسي واحد.
- لا توضع خلفية شديدة التشبع خلف نص طويل.
- الفراغ جزء من التسلسل البصري وليس مساحة مهدرة.

## 6. تجربة التفاعل

### التدفق الأساسي للطالب
```
دخول
→ مسارك اليوم
→ قراءة الخطوة التالية
→ بدء النشاط
→ إكماله
→ ظهور الإنجاز/الشارة
→ العودة إلى الملخص
```

### انتقال الأقسام
- انتقال بصري خفيف فقط.
- لا تستخدم مؤثرات تعطل القراءة.
- يحترم النظام `prefers-reduced-motion`.

### Onboarding
يظهر لأول زيارة فقط في 3 خطوات:
1. الخطوة التالية أولًا.
2. الأقسام الأربعة.
3. معنى الشارات والتقدم الحقيقي.

لا يعاد ظهوره بعد إكماله أو تخطيه.

## 7. التحفيز Gamification
تم تجنب «النقاط الافتراضية» التي لا ترتبط بالتعلم.

الشارات الحالية:
- 🌱 بداية قوية: أول مهمة مكتملة.
- 🔥 مثابر: 3 مهام مكتملة أو أكثر.
- 🎯 متقن: نتيجة 90٪ فأعلى.
- 🧭 متنوع: إنجاز أكثر من نوع تدريب.

ويظهر أيضًا:
- عدد المهام المنجزة.
- عدد المهام النشطة.
- متوسط المهام المكتملة.
- الاستمرارية بالأيام المتتالية.

## 8. الصفحات الحيوية

### شاشة الدخول
- تبويبان فقط: معلم / طالب.
- زر CTA واحد واضح لكل نوع حساب.
- الدخول التجريبي مطوي.
- دعم Enter عبر form حقيقي.
- التركيز ينتقل تلقائيًا لأول حقل.
- حقول الطالب محدودة إلى الاسم، الفصل، وآخر 3 أرقام.

### لوحة الطالب
- «مسارك اليوم» في أعلى أول صفحة.
- CTA واحد للخطوة التالية.
- ملخص 4 مؤشرات فقط.
- شارات + تقدم المواد.
- بقية التفاصيل أسفل الأولوية الأساسية.

### صفحة المادة
ملخص المواد يعرض القراءة/الرياضيات/العلوم:
- المهام المكتملة.
- إجمالي المهام.
- نسبة تقدم مبسطة.
ولا يكرر محتوى العلاج أو الإثراء.

## 9. المحتوى والإرشاد
قواعد النص:
- فعل واضح أولًا: «ابدأ»، «أكمل»، «افتح».
- تجنب المصطلحات الداخلية للنظام.
- التعليمات الثانوية داخل Details عند الحاجة.
- لا تستخدم «ممتاز» بلا سبب؛ التشجيع مرتبط بإنجاز حقيقي.

## 10. الوصول والاستجابة
- تنقل الطالب على الجوال يبقى 4 أقسام.
- CTA بعرض كامل على الشاشات الصغيرة.
- focus مرئي.
- ألوان الحالة مصحوبة بنص ورمز.
- الوضع الليلي مدعوم.
- `prefers-reduced-motion` مدعوم.
- شاشة الدخول تتحول من عمودين إلى عمود واحد تحت 900px.

## 11. القياس واختبارات A/B

### أحداث UX الفعلية
يتم تسجيل الأحداث التالية فقط:
- `login_success`
- `student_workspace_view`
- `student_section_open`
- `student_task_start`
- `student_task_complete`
- `student_onboarding_complete`
- `student_journey_open`
- `teacher_dashboard_view`

البيانات المخزنة:
- معرف داخلي للحساب.
- نوع الحدث.
- القسم.
- المتغير التجريبي `variant`.
- الزمن منذ فتح الصفحة.

لا يتم تخزين:
- الاسم.
- نص السؤال.
- الإجابة.
- الدرجة في سجل UX.

### KPIs
1. **Activation Rate**
   - طلاب بدأوا مهمة ÷ طلاب فتحوا مساحة الطالب.
2. **Task Completion Rate**
   - طلاب أكملوا مهمة ÷ طلاب بدأوا مهمة.
3. **Median Time to First Action**
   - وسيط `elapsed_ms` لأول `student_task_start`.
4. **Onboarding Completion**
   - `student_onboarding_complete` ÷ أول زيارات مساحة الطالب.
5. **D1 / D7 Return**
   - نسبة الطلاب الذين عادوا في يوم مختلف بعد أول استخدام.
6. **Section Discovery**
   - توزيع فتح الأقسام الأربعة.

### خطة A/B
- A: النسخة السابقة.
- B: UX v3.
- تثبيت النسخة للمستخدم طوال الاختبار.
- مدة مقترحة: 5–10 أيام دراسية.
- لا يعتمد القرار على مدة الجلسة وحدها.
- معيار النجاح الأساسي: تحسن Activation وCompletion دون زيادة واضحة في أخطاء الدخول أو الارتداد.

لم تُختلق نتائج A/B بشرية في هذا التسليم؛ القياس أصبح جاهزًا لجمعها.
