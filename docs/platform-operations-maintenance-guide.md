# دليل تشغيل وصيانة منصة «معلّمي»

## 1. قواعد النشر

1. لا يتم تعديل `main` مباشرة في التغييرات الكبيرة؛ يستخدم فرع باسم واضح مثل `fix/brand-shell` أو `hardening/rls-policies`.
2. أي ملف يظهر في HTML يجب أن يكون موجودًا في `production-files.txt`.
3. أي تعديل على صفحة حية يجب أن يمر عبر GitHub Actions حتى تظهر `Deploy Pages = Success`.
4. لا تعتمد على Ctrl+F5 فقط لتأكيد النجاح؛ راجع نشر Pages ونسخة الملف المنشورة.

## 2. قواعد الأمان

| القاعدة | التطبيق |
|---|---|
| لا حذف جماعي | كل حذف يحتاج ID صريح واختبار واحد محدد |
| لا RLS بدون اختبار | تطبيق policies أولًا في بيئة مراجعة أو بعد نسخة احتياطية |
| لا حفظ مفاتيح حساسة في الكود | لا `service_role` ولا أسرار في GitHub Pages |
| سجلات مهمة | أي حذف/استيراد/تصحيح يجب أن يسجل actor/time/scope |

## 3. تشغيل يومي

- فحص صفحة GitHub Actions بعد كل تعديل.
- فتح الصفحات الحرجة: الرئيسية، إنشاء اختبار، التصحيح الآلي، التحليل، حساب المعلم.
- اختبار الشعار في بداية الدخول.
- إنشاء اختبار ورقي تجريبي صغير والتأكد من الطباعة والتظليل والتحليل.

## 4. تشغيل أسبوعي

- مراجعة Supabase Advisors: Security + Performance.
- مراجعة أي أخطاء من الطلاب أو المعلمين وتصنيفها: واجهة، بيانات، طباعة، صلاحيات.
- اختبار نسخة PDF واحدة لكل: ورقة الأسئلة، ورقة التظليل، التحليل الرسمي.

## 5. قائمة تحقق قبل النشر

```text
[ ] لا يوجد ملف HTML يشير إلى أصل غير موجود في production-files.txt
[ ] الشعار ظاهر على صفحات الشاشة
[ ] لا توجد أخطاء console حرجة
[ ] التصحيح الآلي يفتح دون كسر اختيار الفصل
[ ] تحليل الاختبار الورقي يطبع A4
[ ] لا توجد عمليات حذف واسعة أو SQL غير مقيد
[ ] GitHub Actions نجح بالكامل
```

## 6. خطة التعافي من الأعطال

| العطل | الإجراء |
|---|---|
| صفحة لا تظهر | افحص production-files ثم Actions logs |
| الشعار لا يظهر | تحقق من `moallimi-logo-ui.png` ونسخة cache query |
| التحليل لم يتغير | تحقق من أن الملف موجود في production-files وأن Pages نُشر |
| التصحيح لا يقرأ الورق | افحص جودة PDF وموضع QR ونموذج ورقة التظليل |
| فقد بيانات | لا تنفذ SQL جديد؛ افتح دعم Supabase واطلب export من backup |

## 7. سياسة التغيير

التغييرات تنقسم إلى:

- عاجلة: إصلاح كسر أو شعار أو طباعة لا تعمل.
- تشغيلية: تحسين مسار أو نص أو تنظيم.
- هيكلية: دمج CSS/JS أو تغيير قاعدة البيانات.

التغييرات الهيكلية لا تنفذ في يوم دوام أو قبل اختبار فعلي للطلاب.
